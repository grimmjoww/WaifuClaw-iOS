# Session & Context: source-to-iOS parity audit

## Scope and verdict

**In scope only:** `nmem_session`, `nmem_eternal`, and `nmem_recap` from the selected NeuralMemory fork at commit **`2015cb9b0973a6fe14a3bc547c932d64d6ced203`**. This is a source inspection of `/home/ubuntu/neural-memory-source-audit` and `/home/ubuntu/waifuclaw-ios-build`; no audited source was changed and no test execution is claimed.

**Readiness rule used:** a tool is **ready** only when the iOS implementation reproduces the tool's material contract, the native agent can advertise and dispatch that exact tool during its ordinary cycle, and focused XCTest coverage (including a lifecycle exit case) proves it. Any other state is **partial** or **missing**. On that rule, **no scoped tool is ready**.

**Shared upstream schema behavior:** all three schemas are additionally given a `parameters` alias and injected `compact` plus `token_budget` properties by `_with_parameters_alias` ([`tool_schemas.py:47-77`](file:///home/ubuntu/neural-memory-source-audit/src/neural_memory/mcp/tool_schemas.py#L47-L77)). The tool-specific rows below focus on their material Session & Context inputs and behavior; a parity adapter must not silently drop those shared response controls.

## Actual iOS reachability

1. A user enables sharing **per project** in Memory. The toggle's copy says only up to three matching approved facts may be sent to the configured model and IDs are recorded locally ([`NativeMemoryView.swift:285-304`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory/NativeMemoryView.swift#L285-L304)).
2. On `NativeAgentController.run`, the controller derives `useMemory` from that consent and calls `NativeAgentEngine.stream` ([`NativeAgentController.swift:124-170`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentController.swift#L124-L170)).
3. The engine injects local recall only before the provider cycle and only when workspace/file tools remain available. JEV can deliberately turn `offerFileTools` off for general questions, which also disables that memory injection ([`NativeAgentEngine.swift:92-107, 135-165`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift#L92-L165)).
4. The subsequent model-tool loop offers file tools (and possibly `propose_edit`) only; it has no `nmem_session`, `nmem_eternal`, or `nmem_recap` route ([`NativeAgentEngine.swift:176-178, 220-274, 326-343`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift#L176-L178)). Thus existing automatic fact injection is **not** agent-call reachability for any upstream Session & Context tool.

## Implementation-boundary finding: do not count MCP connector or Python MCP as native parity

The selected upstream project is MIT licensed (`/home/ubuntu/neural-memory-source-audit/LICENSE`) and exposes its 63 tools through **MCP stdio**. Its guide specifies JSON-RPC 2.0 over stdin/stdout and starts `nmem-mcp` / `python -m neural_memory.mcp` ([`docs/api/mcp-tools.md:1-7`](file:///home/ubuntu/neural-memory-source-audit/docs/api/mcp-tools.md#L1-L7); [`docs/guides/mcp-server.md:494-512`](file:///home/ubuntu/neural-memory-source-audit/docs/guides/mcp-server.md#L494-L512)). The Python `MCPServer` uses shared SQLite brain storage and composes `SessionHandler` and `EternalHandler` ([`server.py:7-18, 88-176`](file:///home/ubuntu/neural-memory-source-audit/src/neural_memory/mcp/server.py#L7-L18)). That is an upstream desktop/Python MCP implementation, **not an iPhone-native implementation**.

WaifuClaw's `NativeMCPConnector` is a separate **remote HTTPS Settings/UI connector**: its header says models must never receive the connector or call approval; discovery is Settings-only; the UI shows exact JSON and obtains user consent before a one-use remote call ([`NativeMCPConnector.swift:4-5, 31-32, 117-190`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/MCP/NativeMCPConnector.swift#L4-L5)). Its UI is the caller of `approveToolCall`/`executeToolCall`, not `NativeAgentEngine` ([`NativeMCPView.swift:121-131`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/MCP/NativeMCPView.swift#L121-L131)). It therefore cannot count as local memory behavior, named-tool routing, or parity for this audit.

Conversely, the existing `LocalNeuralMemoryStore` is honestly phone-native: it is actor-isolated SQLite, per-project, with no cross-project query, remote call, model invocation, or credential storage ([`LocalNeuralMemoryStore.swift:20-25`](file:///home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory/LocalNeuralMemoryStore.swift#L20-L25)). This is valuable infrastructure, but its deliberately narrow, explicitly approved fact model should not be overstated as completion of the three upstream tools.

## Risks / release blockers

- **False parity claim:** no exact scoped tool name occurs in Swift tool offerings or dispatch; the claimed three-tool native surface is currently 0/3 ready.
- **Lifecycle gap:** current memory recall is pre-prompt best-effort and may be disabled by workspace/JEV gating. It is neither a session-start `nmem_recap` call nor a session-end `nmem_session(end)` action.
- **Semantic/data-model gap:** upstream typed graph records, tags/priorities, replacing project context, session tombstones/summaries, bounded levels/topics, and status accounting have no local equivalents.
- **Privacy/consent regression risk:** the current phone design intentionally requires specific user approval for every local write and a separate per-project sharing opt-in. Agent-originated eternal/session writes must retain a reviewable consent path; automatic model capture would violate the existing design intent.
- **Connector confusion risk:** remote manual MCP and a Python stdio process must remain explicitly separate from native phone parity; neither provides native agent-cycle routing in this checkout.
