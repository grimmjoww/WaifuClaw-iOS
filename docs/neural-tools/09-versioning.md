# NeuralMemory iOS Audit — Versioning and Transfer

**Scope:** Exactly `nmem_version`, `nmem_transplant`, and `nmem_conflicts`; no other tool domain was assessed.

**Upstream baseline:** `/home/ubuntu/neural-memory-source-audit` at `2015cb9b0973a6fe14a3bc547c932d64d6ced203` (requested abbreviated SHA: `2015cb9`). The checked upstream repository is **MIT**-licensed (`LICENSE:1-20`). It is a Python MCP server whose tool reference describes **63 tools via MCP stdio** (`docs/api/mcp-tools.md:1-7`), whose entry point is `python -m neural_memory.mcp` (`src/neural_memory/mcp/server.py:10-18`), and whose dispatch maps the three exact names (`src/neural_memory/mcp/server.py:357-425`). This is **not** an iOS implementation.

## Decision rule

A tool is **Ready** only if all three are present: (1) exact upstream-equivalent semantic behavior, (2) native `NativeAgentEngine` tool definition plus routing to that behavior, and (3) focused XCTest coverage including a successful agent-cycle exit. **No tool is Ready.** “Partial” below means a relevant local building block exists, not that the MCP tool is usable or equivalent.

## Native reachability and permission findings

1. **The local component is intentionally narrower than the Python server.** `LocalNeuralMemoryStore` is an on-device SQLite actor for explicit user-approved facts; its only production write requires `.userApproved` (`LocalNeuralMemoryStore.swift:106-198`). The Swift data model contains fact/source/provenance/timestamps and two graph-edge kinds, not upstream brains/fibers/tags/types/lifecycle/conflicts (`LocalNeuralMemoryModels.swift:3-241`). Its mapping document expressly says it is “a new, deliberately small Swift implementation,” not a full port (`Local/Memory/UPSTREAM.md:14-16,70-74`).

2. **Memory-enabled agent runs only retrieve up to three local facts into prompt context.** `NativeAgentEngine` creates a `LocalNeuralMemoryStore`, recalls selected-project facts, and appends them as untrusted context only when memory sharing, a workspace, and file tools are enabled (`WaifuClaw/Local/Agent/NativeAgentEngine.swift:135-165`). The per-project toggle says it may send up to three matching facts to the configured model provider (`NativeMemoryView.swift:285-302`); `NativeMemoryConsent` stores only that sharing preference (`NativeMemoryConsent.swift:3-29`). This is neither a versioning/transfer/conflict capability nor authorization to mutate memory.

3. **No exact native agent tools exist.** The agent offers only `list_files`, `read_file`, and conditionally `propose_edit` (`NativeAgentEngine.swift:171-178,326-343`). Its tool executor switches only on `list_files`/`read_file`; unrecognized calls return a tool error (`:298-323`). Thus the three names are neither exposed to a model nor routable through an agent cycle. Existing focused tests cover five store behaviors and three engine behaviors only (`WaifuClawTests/NativeNeuralMemoryTests.swift:16-179`; `WaifuClawTests/NativeAgentEngineTests.swift:6-109`); repository search found no exact `nmem_version`, `nmem_transplant`, or `nmem_conflicts` test/use.

4. **Remote MCP must not be credited as native parity.** The iOS MCP slice supports only remote HTTPS Streamable HTTP and explicitly has **no stdio** (`WaifuClaw/Local/MCP/NativeMCPModels.swift:4-5`). Discovery is for Settings UI, not agent/model context (`NativeMCPConnector.swift:31-32`); remote tool execution requires an exact, one-use UI approval (`:117-160`). Even if a user manually registers an upstream remote server exposing these names, that is a remote Python-server operation with external state/effects, not phone-native memory behavior, agent routing, or parity test coverage.
