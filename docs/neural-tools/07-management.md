# Neural Memory → WaifuClaw iOS Audit: Memory Management

**Scope:** exactly the seven requested upstream MCP tools: `nmem_edit`, `nmem_forget`, `nmem_pin`, `nmem_consolidate`, `nmem_drift`, `nmem_review`, and `nmem_alerts`.

**Upstream inspected:** `/home/ubuntu/neural-memory-source-audit` at commit `2015cb9` (verified `HEAD`).

**iOS inspected:** `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory` and `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift`, plus direct callers and XCTest files.

## Decision rule and result

> **Ready** requires all three: exact upstream behavior, an iOS agent tool schema/dispatcher route that can reach it in a real agent cycle, and passing behavioral plus agent-lifecycle XCTest coverage. A manual screen, a local data-store primitive, a future-looking placeholder, or a manually configured remote MCP server does **not** meet the rule.

**Result: 0/7 ready.** `nmem_edit` and `nmem_forget` are **partial** only because the local UI/store provides adjacent manual fact capture/deletion primitives. The other five are **missing**. Every exact upstream adapter remains unimplemented, including routing and test coverage.

## Cross-cutting reachability and test evidence

1. **The native memory feature is a local, explicit-fact graph—not an iOS port of NeuralMemory MCP.** `LocalNeuralMemoryStore` is actor-isolated SQLite for user-approved facts; each table/lookup is project-scoped and it makes no remote/model/credential call (`/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory/LocalNeuralMemoryStore.swift:20-25`). Its production write API is intentionally `capture(..., approval: .userApproved)` with no auto-capture route (`:106-145`). The Memory UI supports manual capture, recall, single deletion, project purge, and export (`NativeMemoryView.swift:89-171`).

2. **An enabled memory setting only supplies read context to the agent.** Per-project consent is keyed to a 64-character project ID (`NativeMemoryConsent.swift:3-29`). The controller passes that setting as `memoryEnabled` (`NativeAgentController.swift:154-165`); the engine then recalls up to three facts into prompt context only when `memoryEnabled`, file tools, and a workspace are present (`NativeAgentEngine.swift:135-165`). This is not a management-tool route or mutation authorization.

3. **No selected tool can be reached in an iOS agent cycle today.** `NativeAgentEngine` constructs its offered tools from only `fileTools` plus optional `proposalTool` (`:176-178`). `fileTools` contains `list_files` and `read_file`, and its switch rejects every other name as unavailable (`:298-343`). Thus a provider-supplied `nmem_*` call is not merely untested; it is not offered and would resolve as unavailable if supplied.

4. **Existing tests do not close the parity gap.** `NativeNeuralMemoryTests.swift:16-179` tests local persistence, project isolation, ranking, direct deletion/purge, and JSON export. `NativeMemoryConsentTests.swift:5-34` tests opt-in/project isolation. `NativeAgentEngineTests.swift:6-109` tests normal completion, denied file paths, and safe `propose_edit`; it has no selected management tool. None supplies exact schemas, handler assertions, or a selected-tool agent-cycle exit assertion.

5. **The upstream server is MIT Python MCP over stdio, not a phone-native implementation.** The upstream license is MIT (`/home/ubuntu/neural-memory-source-audit/LICENSE:1-21`), and `run_mcp_server` reads JSON-RPC lines from stdin, dispatches them, and writes stdout responses (`src/neural_memory/mcp/server.py:826-913`). The seven functions are registered in its Python server dispatch (`server.py:381-405`). Reusing that process remotely would not implement equivalent native Swift behavior.

6. **Remote MCP is explicitly excluded from parity.** WaifuClaw separately has a manually configured public-HTTPS connector: `NativeMCPRegistry.addServer` (`WaifuClaw/Local/MCP/NativeMCPRegistry.swift:38-46`) and `NativeMCPConnector.discover` (`WaifuClaw/Local/MCP/NativeMCPConnector.swift:33-117`). Its discovered strings are untrusted display data and no model tool is created until exact server/tool enablement and `NativeMCPUserConsent.explicitUserApproval` (`NativeMCPModels.swift:70-100`). It may manually connect to a remote MCP server, but that is **not** a phone-native `LocalNeuralMemoryStore` implementation and does not satisfy any row above.

## Implementation gate before any status can change to Ready

For each name, require: (1) the exact input/output/error semantics evidenced above, adapted to deterministic project-scoped Swift data; (2) a deliberate iOS permission/approval policy for persistent or destructive mutation; (3) an exact `AgentToolDefinition` plus dispatcher path in `NativeAgentEngine`; (4) the named direct XCTest and lifecycle exit test passing; and (5) a test proving no cross-project read/write. Background maintenance and notification behavior must be represented as best-effort iOS-native services with observable status, never assumed from the upstream Python scheduler.
