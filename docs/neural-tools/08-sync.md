**Upstream inspected:** `/home/ubuntu/neural-memory-source-audit` at `2015cb9b0973a6fe14a3bc547c932d64d6ced203` (the requested `2015cb9`). **iOS inspected:** `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory` and `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift`, plus the directly relevant UI, MCP, and XCTest sources named below. ## Verdict

**Native-ready exact tools: none (0/4).**

A status is **Ready** only if the iOS code has the exact tool behavior, it is offered and routed in the real `NativeAgentEngine` cycle, and XCTest covers both the behavior and successful agent-cycle exit. **Partial** means a real native building block exists but it is not the upstream tool. **Missing** means there is no corresponding native behavior/state/routing. A local JSON export, generic remote MCP connector, or placeholder-like absence does **not** establish native Cloud Sync and Backup parity.

## Reachability finding: none of the four exact names can execute in the iOS agent today

`NativeAgentController` passes the per-project `memoryEnabled` switch to the engine (`Local/Agent/NativeAgentController.swift:153-170`). In the engine, that branch only opens `LocalNeuralMemoryStore`, recalls at most three approved project facts, and adds text to the model’s system context (`NativeAgentEngine.swift:135-165`). It neither creates an MCP memory tool nor performs sync/backup.

The actual model tool list is only `fileTools` (and optional `propose_edit`) (`NativeAgentEngine.swift:171-178,326-342`). `performTool` recognizes only `list_files` and `read_file`; every other name returns `Tool error: unavailable tool …` (`:298-323`). Therefore a model call named any of the four audited names is not a real native operation; it is merely rejected and logged as a tool failure by the generic loop (`:220-274`). Existing engine tests prove ordinary completion and file/patch behavior, not any audited tool (`WaifuClawTests/NativeAgentEngineTests.swift:6-108`).

## MCP and licensing boundary

The upstream is **MIT-licensed Python** (`/home/ubuntu/neural-memory-source-audit/LICENSE:1-13`). Its MCP server documentation says it exposes tools through MCP for desktop clients and is launched as `python -m neural_memory.mcp` / `nmem-mcp` (`src/neural_memory/mcp/server.py:1-18`); the tool reference explicitly describes **63 tools via MCP stdio** (`docs/api/mcp-tools.md:1-7`). The Python server dispatches the four names to the handler methods (`server.py:357-390`). That is not an embedded Swift implementation.

WaifuClaw’s `Local/MCP` is a **manual remote Streamable HTTP connector**, not native memory parity: discovery is Settings/UI-only (`NativeMCPConnector.swift:31-33`), each exact JSON call needs one-use UI approval (`:117-190`), and the UI expressly says stdio/locally run servers are unavailable and MCP tools are not automatically offered to the coding agent (`NativeMCPView.swift:207-218`). Even if a user manually points that connector at a hosted upstream server, it is a remote server operation with its own data/credentials—not a phone-native implementation of these four tools and not reachable through the agent cycle audited here.

## Implementation gate before any “Ready” claim

For each exact name, require all of the following: (1) an explicit Swift tool schema/handler that matches documented arguments and result/error contract; (2) durable on-device state and secure network/credential implementation appropriate to that operation; (3) a named, consent-gated agent tool registration and router branch in `NativeAgentEngine`; (4) ordinary XCTest behavior tests using deterministic fake transport/storage; (5) a provider-driven lifecycle XCTest proving successful tool call, result reinjection, `run.completed`, `.finished`, and finite stream; and (6) negative tests proving no network side effect or credential leakage without consent. Until then, the accurate status remains **0/4 ready**.
