# NeuralMemory source-to-iOS audit — Analytics and Health

**Scope.** This is a read-only comparison restricted to the five requested upstream MCP tools: `nmem_stats`, `nmem_health`, `nmem_evolution`, `nmem_habits`, and `nmem_narrative`.

**Source revisions and boundary.** The inspected upstream checkout is `/home/ubuntu/neural-memory-source-audit` at verified full SHA `2015cb9b0973a6fe14a3bc547c932d64d6ced203` (requested abbreviated SHA `2015cb9`). It is MIT-licensed (`/home/ubuntu/neural-memory-source-audit/LICENSE:1-20`). Its reference states that the 63 tools are available through **MCP stdio** (`docs/api/mcp-tools.md:1-7`), and the Python server is launched as `python -m neural_memory.mcp` / `nmem-mcp` (`src/neural_memory/mcp/server.py:10-18`). This is not a phone-native implementation.

The iOS implementation under `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory` is a separate actor-isolated, SQLite-backed, **per-project** store. It explicitly has no cross-project lookup, remote call, model invocation, or credential storage (`LocalNeuralMemoryStore.swift:20-25`). Its production write path stores one explicitly user-approved fact (`LocalNeuralMemoryStore.swift:106-197`), while its actual retrieval is bounded deterministic anchor/co-occurrence spreading activation (`LocalNeuralMemoryStore.swift:220-332`).

## Readiness rule used

A tool is **Ready** only if the phone implementation has all three of these: (1) the exact upstream behavior and persistent data dependencies, (2) a named native tool schema/dispatcher route that the agent is actually offered, and (3) exact XCTest coverage including a successful agent-cycle exit. **Partial** means a real local substrate overlaps with a portion of the feature but does not meet that rule; **Missing** means no meaningful implementation of the named behavior exists. A local graph, a UI count, an audit event, placeholder text, or an unrelated remote/manual connector is not counted as native parity.

All upstream MCP schemas receive injected `compact` and `token_budget` properties (`tool_schemas.py:36-78`). Thus the parameter notes below describe tool-specific inputs plus that common injection.

## Agent-cycle reachability finding

**None of the five named tools is reachable in the current native agent cycle.** `NativeAgentEngine` does one optional, consented top-three local recall before composing the model prompt (`/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift:135-165`). It then presents only file tools and an optional edit-proposal tool (`:171-178,326-343`). Its generic dispatcher accepts `list_files`, `read_file`, and otherwise returns `Tool error: unavailable tool` (`:298-323`). Although the run loop correctly records tool selection/completion and exits to `.finished` on a text-only final turn (`:183-276`), no analytics/health schema, handler, route or lifecycle test is present.

`NativeAgentController` sends the memory-enabled flag only after per-project consent (`/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentController.swift:158-170`). The Memory screen makes that boundary explicit: local facts can be recalled on-device even when sharing is off; only up to three matching facts may be added to a configured-model request after opt-in (`/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory/NativeMemoryView.swift:285-303`). Native consent itself defaults off and is project-isolated (`WaifuClawTests/NativeMemoryConsentTests.swift:5-35`).

## Manual remote MCP is expressly excluded from parity

The iOS MCP screen is a **manual public-HTTPS connector**, not phone-native memory and not agent routing. Its source says remote MCP is not an iOS system permission and the screen never enables/calls a discovered tool on behalf of a model (`/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/MCP/NativeMCPView.swift:149-150`). It supports MCP 2025-11-25 only, excludes stdio/local servers, and states that MCP tools are not automatically offered to the coding agent (`:213-217`). Each manual call binds an explicit confirmation to the exact JSON (`:120-131`). Therefore it cannot turn the upstream MIT Python **stdio** server into a native implementation of any row above, even if a user manually connects to a remote server advertising one of these names.

## Bottom line

- **Native-ready tools:** none (`0/5`).
- **Partial local substrate:** `nmem_stats`, `nmem_habits`, `nmem_narrative`; none has a named native tool, exact behavior, agent routing or exact XCTest/lifecycle coverage.
- **Missing behavior:** `nmem_health` and `nmem_evolution`.
- **Strict parity conclusion:** all five named upstream tools remain unimplemented as native, agent-reachable Analytics and Health parity on iOS.
