# Cognitive Reasoning — NeuralMemory source-to-iOS audit

**Audit scope:** exactly the eight upstream tool names in this document: `nmem_hypothesize`, `nmem_evidence`, `nmem_predict`, `nmem_verify`, `nmem_cognitive`, `nmem_gaps`, `nmem_schema`, and `nmem_explain`. No other domain was assessed.

**Sources audited:**

- Upstream selected checkout: `/home/ubuntu/neural-memory-source-audit` at `2015cb9b0973a6fe14a3bc547c932d64d6ced203` (requested short SHA `2015cb9`).
- iOS checkout: `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Memory` and `/home/ubuntu/waifuclaw-ios-build/WaifuClaw/Local/Agent/NativeAgentEngine.swift`, with the directly relevant UI, consent, MCP, and XCTest files inspected for reachability.
- No source code was edited. This report is the only created artifact.

## Decision rule and transport boundary

> **Ready** would require all three: exact upstream-observable behavior, an on-device agent tool route that can invoke it during a real agent cycle, and XCTest coverage of both behavior and successful cycle exit. A data-structure resemblance, a remote MCP connector, a manual connector configuration, or placeholder/UI text does **not** satisfy this rule.

The upstream project is an **MIT-licensed Python** implementation (`/home/ubuntu/neural-memory-source-audit/LICENSE:1-13`). Its tool reference says that 63 tools are exposed through **MCP stdio** (`docs/api/mcp-tools.md:1-7`), and the real MCP server maps all eight requested names to Python handlers (`src/neural_memory/mcp/server.py:391-398`). This is distinct from a phone-native implementation.

The current iOS local store explicitly declares itself a deliberately small new Swift/Foundation/SQLite3 implementation, not a Python port (`WaifuClaw/Local/Memory/UPSTREAM.md:14-16`), and explicitly excludes cognitive layers and an upstream compatibility protocol (`UPSTREAM.md:70-74`). Its public production capabilities are approved fact `capture` and token/co-occurrence `recall` (`LocalNeuralMemoryStore.swift:106-198`, `:220-331`); its models expose only `factContainsAnchor` and `coOccurs` synapse kinds (`LocalNeuralMemoryModels.swift:122-128`).

The existing `NativeMCPConnector` is a **remote** MCP façade (`Local/MCP/NativeMCPConnector.swift:4-6`), with explicit discovery/enablement and per-call approval (`:102-160`). Its transport is URLSession POST Streamable HTTP and expressly has no local process (`NativeMCPTransport.swift:16-18`). It cannot be counted as native NeuralMemory parity, even if a user manually connects an upstream server.

## Current native reachability and test baseline

- When the user has enabled per-project sharing, the controller passes `memoryEnabled` to `NativeAgentEngine` (`Local/Agent/NativeAgentController.swift:157-170`). The engine only recalls up to three local facts and puts them into the model's **system prompt** (`NativeAgentEngine.swift:135-165`). This is context injection, not a cognitive tool call.
- The engine offers only `list_files`, `read_file`, and conditionally `propose_edit` (`NativeAgentEngine.swift:176-178`, `:326-342`); its executable switch handles only the two file tools (`:298-320`). Thus none of the eight names can be selected and executed in the current native agent cycle.
- Existing local-memory tests validate persistence, project isolation, spreading recall, deletion/purge, and export/provenance (`WaifuClawTests/NativeNeuralMemoryTests.swift:16-179`). Existing engine tests validate generic completion and file/proposal behavior (`WaifuClawTests/NativeAgentEngineTests.swift:6-109`). There is no exact cognitive-tool test or agent lifecycle test for any of the eight names.
- Approved-memory sharing itself is correctly opt-in and project-isolated (`NativeMemoryConsent.swift:3-29`; tests at `NativeMemoryConsentTests.swift:6-34`). This is a privacy control for prompt injection, not permission or routing for cognitive mutations.

## Findings and implementation gate

1. **Native ready tools: none (0/8).** All eight exact names are absent from native Swift tool definitions/routing. `NativeAgentEngine` will mark any unrecognized name unavailable rather than execute native memory behavior (`NativeAgentEngine.swift:298-320`).
2. **All eight are unimplemented as phone-native cognitive tools.** The only useful overlap is local token/co-occurrence graph recall and its `why` explanation; it is an intentionally restricted local-memory primitive, not `nmem_explain` or any other cognitive tool.
3. **Do not use remote MCP as a completion claim.** The remote connector’s manual discovery/allowlist/one-use approval flow is a security boundary for an external HTTP server, not a local `NeuralStorage`/MCP-stdio engine; no current `NativeAgentEngine` routing integrates it.
4. **Privacy is a design constraint, not a completed adaptation.** Today, writes require exact approval and model sharing is per-project opt-in. A cognitive implementation must reconcile that policy with upstream operations that create multiple derived records/edges; tool calls must not silently convert model output, recalls, or query misses into persisted beliefs/evidence/gaps.
5. **Recommended implementation sequence:** first introduce a separately tested local cognitive schema and pure functions (hypothesis/evidence/prediction/verify); then add gaps, hot index, versioning, and graph explanation; only then expose exact local tool definitions and a dispatcher in `NativeAgentEngine`, with the per-row lifecycle tests as the release gate. Do not claim the optional NumPy/Koopman prediction path unless an explicitly native implementation is added.
